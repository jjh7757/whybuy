## 2. 이 프로젝트의 중심 요소

**6번 판단 근거입니다.**

```
종목 · 시세 · 계좌  →  주문  →  판단 근거  →  회고
                                    ↑
                            이 요소가 없으면
                        이 프로젝트는 KIS 앱의 열화판입니다
```

계좌 조회와 시세 조회는 증권사 앱이 더 잘합니다. 이 서비스가 증권사 앱과 다른 지점은 **주문에 근거를 붙여 저장하고 다시 보여준다**는 것 하나입니다.

## 3. 🔴 프로젝트 2에서 달라진 요소

### 3.1 삭제 — 대화 세션 / 대화 맥락

프로젝트 2는 `conversation_context` 테이블로 `그거 10주 사줘`의 "그거"를 해석했습니다.

웹에서는 **주문 화면이 종목을 이미 들고 있습니다.** 사용자가 `삼성전자` 페이지에서 수량을 입력하므로 지칭 대상이 애초에 모호하지 않습니다. **요소 자체가 사라집니다.**

### 3.2 삭제 — 의도

프로젝트 2는 자연어를 분류해 의도를 만들어냈습니다. 웹에서는 **사용자가 누른 버튼이 곧 의도**입니다. 추론할 대상이 아니라 입력값입니다.

### 3.3 신규 — 접근토큰이 저장 대상이 됨

프로젝트 2 데이터 구조 문서는 접근토큰을 **저장하지 않는다**고 명시했습니다. n8n Credential이 관리했기 때문입니다.

Vercel에는 그런 것이 없습니다. Route Handler는 요청마다 새로 뜨므로, 캐시하지 않으면 **매 요청마다 토큰을 새로 발급**하게 됩니다. KIS는 토큰 발급 호출 빈도를 제한하므로 곧 차단됩니다.

**따라서 `kis_tokens` 테이블을 신설합니다.** 프로젝트 2의 원칙을 뒤집는 결정이고, 그 이유는 실행 환경이 바뀌었기 때문입니다.

### 3.4 신규 — AI 회고 코멘트

근거가 누적되어야만 생기는 요소입니다. 대화형에서는 누적을 보여줄 자리가 없어 존재할 수 없었습니다.

## 4. 요소 → 화면 매핑

```
/  계좌 대시보드
   ├── 모의투자 계좌 (2)
   ├── 보유 종목 (3)
   └── AI 해석 (9)          ← AI-1

/trade  종목 조회와 주문
   ├── 종목 (1)
   ├── 시세 (4)
   ├── AI 해석 (9)          ← AI-1
   ├── 주문 (5)
   └── 판단 근거 (6)         ← 입력 필수

/journal  근거 회고
   ├── 주문 (5)
   ├── 판단 근거 (6)
   ├── 시세 (4)             ← 당시가 대비 현재가
   └── AI 회고 코멘트 (10)   ← AI-2
```

**화면이 3개인 것은 우연이 아닙니다.** 요청서가 "화면 3개짜리 서비스가 완성되는 것이 화면 10개짜리가 절반만 되는 것보다 낫다"고 명시했고, 도메인 요소를 묶어 보니 실제로 3개로 떨어졌습니다.

## 5. 저장하지 않는 데이터와 그 이유

| 데이터 | 이유 |
|---|---|
| 예수금·보유종목·수익률 | 실시간으로 변합니다. 저장하면 곧 틀린 값이 됩니다 |
| 현재가·등락률 | 동일 |
| KIS 계좌번호 | 환경변수. DB·화면·문서에 남기지 않습니다 |
| AI 생성 문장 전문 | 매번 새로 생성합니다. 생성했다는 사실만 이벤트로 남깁니다 |

### 예외 — 주문 시점의 가격은 저장합니다

`orders.expected_price`는 **저장합니다.** 시세는 변하지만 **"내가 68,000원일 때 저평가라고 판단했다"는 사실은 변하지 않기** 때문입니다. 이 값이 없으면 회고 화면의 당시가 대비 현재가 비교가 불가능합니다.
