# 왜샀어 (WhyBuy)

**매수·매도 버튼을 누르기 전에 "왜 사는지/파는지"를 반드시 적게 하고, 그 근거를 되돌아보게 하는 모의투자 도구입니다.**

🔗 **배포 주소**: https://whybuy-gray.vercel.app

---

## 무엇을 해결하려고 했는가

증권사 앱은 무엇을 샀는지는 보여주지만 **왜 샀는지는 어디에도 남지 않습니다.**
그래서 며칠 뒤에 자기 판단을 설명할 수 없고, 설명할 수 없으면 그 판단이 옳았는지 배울 수도 없습니다.

이 서비스는 KIS 모의투자 계좌에 실제로 주문을 넣되, **근거를 고르지 않으면 주문 버튼이 눌리지 않습니다.**

## 화면 3개

| 화면 | 하는 일 |
|---|---|
| `/` 계좌 | 내 가상 투자금·주문에 쓴 금액·남은 예산, 보유종목·평가손익, **대기중인 지정가 주문(체결 확인·취소)** + **AI가 초보자 언어로 해석** |
| `/trade` 종목·주문 | 검색 또는 인기 종목 → **탭 3개**(차트·호가 / 종목정보 / 공시뉴스) → 수량·근거 입력 → 매수·매도 주문 |
| `/journal` 회고 | 지난 주문과 근거 목록 + 당시가 vs 현재가 + **AI 회고 코멘트** |

> 🔄 **계좌 화면은 "예수금"을 보여주지 않습니다.** 계획은 KIS 계좌 잔고를 그대로 띄우는 것이었는데, 모의계좌 1개를 여러 방문자가 나눠 쓰다 보니 **계좌 잔고에 남의 주문과 서비스 이전부터 있던 종목이 섞여** 있었습니다. 그걸 "내 계좌"로 보여주면 사용자가 사지도 않은 종목을 자기 것으로 읽게 됩니다. 그래서 8/6에 **내 주문 기록(`orders`) 집계 기준**으로 갈아엎었습니다. KIS는 보유 종목의 현재가를 얻는 데만 씁니다.

### `/trade`의 탭 3개

| 탭 | 내용 |
|---|---|
| 차트·호가 | 종가 그래프(일/주/월/년 + 분봉, 호버 툴팁), 오늘·52주 범위, 시가·거래량·업종, PER·PBR·EPS·BPS, **AI 해석 버튼** |
| 종목정보 | 재무비율(부채비율·ROE·성장률), 배당 이력 |
| 공시뉴스 | DART 공시·뉴스 원문 목록 (해석 없이 제목·날짜만) |

주문 폼은 오른쪽 칼럼에 고정이라 탭을 옮겨도 계속 주문할 수 있습니다. 첫 방문자에게는 **6단계 스포트라이트 튜토리얼**이 자동 실행됩니다.

## AI 기능 (REQ-02)

| # | 기능 | 입력 | 출력 | 어디에 |
|---|---|---|---|---|
| AI-1 | 계좌 해석 | 내 주문 집계(가상 예산·보유 종목) + KIS 현재가 | `내 예산` / `내 주문` **2구획** | `/` 계좌 |
| AI-1 | 시세 해석 | KIS 시세·지표 + DART 공시 3건 + 구글 뉴스 3건 | `오늘 가격` / `기업 가치 지표` / `읽을 때 주의` (+ 소식이 있으면 `최근 소식`) **3~4구획** | `/trade` 차트·호가 탭 |
| AI-2 | 근거 회고 코멘트 | 저장된 근거 목록 최근 20건 | 편중 지적 + 다음에 물어볼 질문 1개 | `/journal` |

모두 **Gemini API**(`gemini-3.5-flash`, SDK 없이 `generateContent` REST 직접 호출)를 부르며, 입력 데이터가 바뀌면 출력이 바뀝니다. 미리 만들어 둔 응답이 아닙니다.

> 🔄 **출력이 "4문장"이 아니라 구획 형식입니다.** 계획은 자유 텍스트 4문장이었는데, 실제로 붙여보니 문단이 통으로 나와 화면에서 읽기 어려웠습니다. `제목|내용` 파이프 형식을 강제하고 화면이 구획별로 쪼개 그리는 방식으로 바꿨습니다. 모델이 형식을 안 지킬 때를 대비해 **형식 파싱 실패 → 빈 줄 문단 분리 → 통짜 한 덩어리** 순의 폴백 체인을 뒀습니다.

> ⚠️ **AI-3(투자용어 설명)은 만들지 않았습니다.** Should Have 1순위였고 "KIS에 의존하지 않는 유일한 기능이라 시연 안전판이 된다"는 이유까지 적어뒀지만, Day 2에 들어온 다른 기능들에 밀렸습니다. REQ-02는 AI 2종으로 이미 충족합니다.

시세 해석(AI-1)은 **DART 공시 API**(거래소공시)와 **Google 뉴스 RSS**에서 그 종목의 최근 소식을 받아와 재료로 함께 씁니다 — 다만 "이런 일이 있었다"는 사실 전달까지만이고, 좋다/나쁘다 평가나 매수·매도 권유로는 이어지지 않게 프롬프트에서 막아둡니다.

**같은 공시·뉴스를 사용자도 `공시뉴스` 탭에서 원문으로 볼 수 있습니다.** AI만 원본을 보면 사용자가 AI 말을 검증할 수 없고, 그건 "AI가 대신 판단해주지 않는다"는 이 서비스의 원칙과 어긋나기 때문입니다.

### AI가 하지 않는 것

```
- 특정 종목의 매수·매도를 권유하지 않습니다.
- 목표 가격이나 수익률을 예측하지 않습니다.
- 사용자의 판단이 옳거나 틀렸다고 평가하지 않습니다.
```

프롬프트에 명시적으로 금지했습니다. 이 서비스의 목적은 **AI가 대신 판단해주는 것이 아니라, 사용자가 자기 판단을 설명하게 만드는 것**이기 때문입니다.

## 🔴 Google 로그인 후 가상 예산 500만원, 계좌는 1개

이 서비스는 **실제 KIS 모의투자 계좌 1개**에 주문을 넣습니다. 정식 서비스라면 계좌를 여러 개 개설해 사용자마다 배정하겠지만, 이번 MVP는 계좌가 1개뿐이라 **DB 안에서 가상으로 예산을 나눕니다.**

```
Google로 로그인 → 계정 확인 (Supabase Auth) → 기본 500만원 가상 예산 지급
→ 이 한도 안에서는 로그인한 누구나 실제 주문을 넣을 수 있음
```

한도를 넘는 주문은 KIS에 전달되지 않고 "가상 예산을 초과했습니다"로 안내됩니다. 회고 화면은 로그인 후 각자 자기 주문만 볼 수 있습니다.

~~**조회·검색·시세는 로그인 없이도 전부 볼 수 있고, 주문 실행 시점에만 로그인이 필요합니다.**~~

🔄 **정확히는 종목 검색·시세만 로그인 없이 볼 수 있습니다.** 계좌(`/`)와 회고(`/journal`)는 **본질적으로 "내 것"을 보여주는 화면**이라 로그인 전에는 보여줄 내용 자체가 없고, 로그인 안내만 뜹니다. 계획 문서에 "조회 화면은 전부 로그인 없이"라고 적었던 것은 화면의 성격을 따져보지 않고 쓴 것이었습니다.

로그인은 계좌를 지키기 위한 잠금장치가 아니라, **예산과 기록을 기기·세션을 넘어 지속시키기 위한 신원 확인**입니다. 방문할 때마다 초기화되는 쿠키 방식 대신 실제 계정을 쓴 이유이기도 합니다.

## 로컬 실행 방법

```bash
git clone https://github.com/jjh7757/whybuy.git
```

```bash
npm install
```

`.env.local`을 만들고 아래 **10개**를 채웁니다.

```
NEXT_PUBLIC_SUPABASE_URL=
NEXT_PUBLIC_SUPABASE_ANON_KEY=
SUPABASE_SERVICE_ROLE_KEY=
GEMINI_API_KEY=
KIS_APP_KEY=
KIS_APP_SECRET=
KIS_ACCOUNT_NO=
KIS_ACCOUNT_PRODUCT_CODE=
KIS_BASE_URL=
DART_API_KEY=
```

> 🔄 **`SUPABASE_SERVICE_ROLE_KEY`와 `DART_API_KEY` 2개가 계획에 없다가 나중에 생겼습니다.** 초안에는 8개만 적혀 있었는데, **이 2개가 없으면 주문과 공시 기능이 동작하지 않습니다.**
>
> - `SUPABASE_SERVICE_ROLE_KEY` — `kis_tokens`·`event_logs`처럼 **로그인 여부와 무관하게 서버만 접근해야 하는** 테이블에 씁니다. 로그인하지 않은 방문자도 시세를 봐야 하므로 세션 키로는 접근할 수 없습니다. 원래는 `security definer` 함수로 대체할 계획이었고 못 했습니다 — [[../03_Data_Event/01_data_structure|데이터 구조]] 7절에 경위와 위험 크기를 적어뒀습니다.
> - `DART_API_KEY` — 8/7에 공시 연동을 넣으면서 추가됐습니다.

Google 로그인은 Supabase 대시보드(Authentication → Providers → Google)에서 클라이언트 ID·시크릿을 등록해야 동작합니다. 앱 코드에는 별도 환경변수가 필요 없습니다.

```bash
npm run dev
```

> ⚠️ `NEXT_PUBLIC_`이 붙은 값만 브라우저에 노출됩니다. **KIS·Gemini 키에는 절대 붙이지 마십시오.**

## 알려진 한계

- 코스피 상장 종목만 검색됩니다(코스닥 제외). 그 외 종목은 안내 후 차단됩니다.
- 시장가·지정가 매수를 모두 지원합니다(8/7 추가). 지정가는 접수 후 바로 체결되지 않을 수 있어 "내 계좌"에서 체결 확인·취소가 필요합니다.
- 매도 주문도 지원합니다(8/7 추가, 근거 유형은 매수와 별도). 보유한 종목에서만 매도 토글이 나타나며, 한도는 가상 예산이 아니라 이 서비스로 보유한 실제 수량입니다.
- 체결 여부는 자동으로 감시하지 않습니다. 지정가 주문만 사용자가 버튼을 눌렀을 때 KIS에 확인합니다(시장가는 접수 즉시 완료로 취급).
- 회고 화면의 현재가는 KIS 조회에 실패하면 `—`로 표시됩니다.
- Google 계정이 없으면 주문을 실행할 수 없습니다. **계좌·회고 화면도 로그인해야 내용이 보입니다** — 로그인 전에는 안내만 뜹니다. 로그인 없이 온전히 쓸 수 있는 것은 종목 검색·시세 화면입니다.
- **지정가 주문의 가격을 서버가 시세와 대조하지 않습니다.** 호가단위 배수인지만 검증합니다. 시장가는 서버가 시세를 다시 조회해 금액을 계산하지만 지정가는 클라이언트가 보낸 값을 그대로 씁니다.
- **매도 주문을 실제 로그인 상태로 끝까지 눌러보지 못했습니다.** 공유 모의계좌라 대신 눌러볼 계정이 없어, 기존 실주문 데이터로 집계 로직만 손으로 대조했습니다.
- **코스피 915종목 전부가 KIS 모의투자에서 시세·주문까지 되는지 전수 검증하지 못했습니다.** 실패 시 화면에 안내가 뜹니다.
- **service role key를 사용합니다.** 원래는 `security definer` 함수로 대체할 계획이었으나 못 했습니다. 키는 서버 환경변수에만 있어 브라우저 번들에 들어가지 않지만, 서버 코드에 버그가 생겼을 때 RLS가 막아주지 못합니다.
- **AI 해석 결과를 캐시하지 않습니다.** 계획에는 "같은 종목 5분 캐시"가 Should로 있었으나 넣지 않았습니다. 자동 호출을 하지 않고 버튼을 눌렀을 때만 부르는 것으로 대부분 해결됩니다.

## 프로젝트 2와의 관계

이 프로젝트는 프로젝트 2에서 작성한 **KIS 모의투자 텔레그램 AI 에이전트 기획서**를 웹으로 옮긴 것입니다.

**옮기면서 새로 가능해진 것**

1. 근거 히스토리를 한 화면에서 되돌아볼 수 있습니다 (대화에서는 스크롤로 찾을 수 없었습니다)
2. 4턴 대화가 1화면으로 압축되어 대기 상태·만료 관리가 사라졌습니다
3. 당시가와 현재가를 표로 대조할 수 있습니다
4. 링크 하나로 아무나 접속할 수 있습니다
5. **근거를 고르지 않으면 주문 버튼이 눌리지 않습니다** — 대화에서는 답하지 않고 이탈할 수 있었습니다

5번 덕분에 근거 기록률이 측정 지표에서 **구조적 보장**으로 바뀌었고, 그래서 목표를 "근거를 남기는가"에서 **"남긴 근거를 되돌아보고 설명할 수 있는가"**로 올릴 수 있었습니다.
