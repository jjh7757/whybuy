# 왜샀어 (WhyBuy)

**매수 버튼을 누르기 전에 "왜 사는지"를 반드시 적게 하고, 그 근거를 되돌아보게 하는 모의투자 도구입니다.**

🔗 **배포 주소**: ⬜

---

## 무엇을 해결하려고 했는가

증권사 앱은 무엇을 샀는지는 보여주지만 **왜 샀는지는 어디에도 남지 않습니다.**
그래서 며칠 뒤에 자기 판단을 설명할 수 없고, 설명할 수 없으면 그 판단이 옳았는지 배울 수도 없습니다.

이 서비스는 KIS 모의투자 계좌에 실제로 주문을 넣되, **근거를 고르지 않으면 주문 버튼이 눌리지 않습니다.**

---

## 화면 3개

| 화면 | 하는 일 |
|---|---|
| `/` 계좌 | 모의계좌 예수금·보유종목·평가손익 + **AI가 초보자 언어로 해석** |
| `/trade` 종목·주문 | 종목 검색 → 시세 확인(AI 해석) → 수량·근거 입력 → 매수 주문 |
| `/journal` 회고 | 지난 주문과 근거 목록 + 당시가 vs 현재가 + **AI 회고 코멘트** |

---

## AI 기능 (REQ-02)

| # | 기능 | 입력 | 출력 |
|---|---|---|---|
| AI-1 | 계좌·시세 해석 | 실시간 잔고 또는 시세 JSON | 초보자용 해석 4문장 |
| AI-2 | 근거 회고 코멘트 | 저장된 근거 목록 최근 20건 | 편중 지적 + 다음에 물어볼 질문 1개 |

모두 **Gemini API**를 호출하며, 입력 데이터가 바뀌면 출력이 바뀝니다. 미리 만들어 둔 응답이 아닙니다.

### AI가 하지 않는 것

```
- 특정 종목의 매수·매도를 권유하지 않습니다.
- 목표 가격이나 수익률을 예측하지 않습니다.
- 사용자의 판단이 옳거나 틀렸다고 평가하지 않습니다.
```

프롬프트에 명시적으로 금지했습니다. 이 서비스의 목적은 **AI가 대신 판단해주는 것이 아니라, 사용자가 자기 판단을 설명하게 만드는 것**이기 때문입니다.

## 데이터 구조 (Supabase)

| 테이블 | 역할 |
|---|---|
| `stocks` | 종목 마스터 (코스피 상위 ⬜종목) |
| `orders` | 매수 주문과 그 결과 |
| `rationales` | **판단 근거** — 이 프로젝트의 핵심 |
| `kis_tokens` | KIS 접근토큰 캐시 (서버리스 환경 대응) |
| `user_wallets` | 방문자별 가상 예산 |
| `event_logs` | 측정용 이벤트 기록 |

주문과 근거는 영구 저장되며, 브라우저를 완전히 종료했다가 다시 열어도 회고 화면에 그대로 남아 있습니다.

## 🔴 Google 로그인 후 가상 예산 500만원, 계좌는 1개

이 서비스는 **실제 KIS 모의투자 계좌 1개**에 주문을 넣습니다. 정식 서비스라면 계좌를 여러 개 개설해 사용자마다 배정하겠지만, 이번 MVP는 계좌가 1개뿐이라 **DB 안에서 가상으로 예산을 나눕니다.**

```
Google로 로그인 → 계정 확인 (Supabase Auth) → 기본 500만원 가상 예산 지급
→ 이 한도 안에서는 로그인한 누구나 실제 주문을 넣을 수 있음
```

한도를 넘는 주문은 KIS에 전달되지 않고 "가상 예산을 초과했습니다"로 안내됩니다. 회고 화면은 로그인 후 각자 자기 주문만 볼 수 있습니다.

**조회·검색·시세는 로그인 없이도 전부 볼 수 있고, 주문 실행 시점에만 로그인이 필요합니다.** 로그인은 계좌를 지키기 위한 잠금장치가 아니라, **예산과 기록을 기기·세션을 넘어 지속시키기 위한 신원 확인**입니다. 방문할 때마다 초기화되는 쿠키 방식 대신 실제 계정을 쓴 이유이기도 합니다.

## 로컬 실행 방법

```bash
git clone ⬜
```

```bash
npm install
```

`.env.local`을 만들고 아래 값을 채웁니다.

```
NEXT_PUBLIC_SUPABASE_URL=
NEXT_PUBLIC_SUPABASE_ANON_KEY=
GEMINI_API_KEY=
KIS_APP_KEY=
KIS_APP_SECRET=
KIS_ACCOUNT_NO=
KIS_ACCOUNT_PRODUCT_CODE=
KIS_BASE_URL=
```

Google 로그인은 Supabase 대시보드(Authentication → Providers → Google)에서 클라이언트 ID·시크릿을 등록해야 동작합니다. 앱 코드에는 별도 환경변수가 필요 없습니다.

```bash
npm run dev
```

> ⚠️ `NEXT_PUBLIC_`이 붙은 값만 브라우저에 노출됩니다. **KIS·Gemini 키에는 절대 붙이지 마십시오.**

## 🔴 하지 않은 것과 그 이유

| 하지 않은 것 | 이유 |
|---|---|
| 자연어 채팅 인터페이스 | 웹에서는 폼이 더 정확하고 빠릅니다. 절감한 시간을 회고 화면에 썼습니다 |
| 체결 자동 감시 (스케줄러) | Vercel에 상주 프로세스가 없습니다. 대신 지정가 주문은 "내 계좌"에서 사용자가 직접 눌러 확인하는 방식으로 8/7에 추가했습니다 |
| 여러 로그인 수단 (이메일 등) | Google OAuth 1개로 충분합니다. KIS 계좌가 1개이므로 사용자를 실제로 나눌 필요는 로그인 자체가 아니라 가상 예산이 담당합니다 |
| 방문자별 실제 계좌 배정 | 정식 서비스라면 계좌를 여러 개 개설해 배정하지만, MVP는 계좌 1개 + 가상 예산으로 시뮬레이션했습니다 |
| 종목 추천 | 유사투자자문 영역이고, 이 프로젝트의 목적과 정반대입니다 |
| 차트·기술적 분석 | 판단 근거와 무관하고 4일에 들어가지 않습니다 |

자세한 내용은 [[02_scope_reduction|범위 축소 설명서]]에 있습니다.

## 알려진 한계

- 코스피 상위 ⬜종목만 검색됩니다. 그 외 종목은 안내 후 차단됩니다.
- 시장가·지정가 매수를 모두 지원합니다(8/7 추가). 지정가는 접수 후 바로 체결되지 않을 수 있어 "내 계좌"에서 체결 확인·취소가 필요합니다.
- 매도 주문도 지원합니다(8/7 추가, 근거 유형은 매수와 별도). 보유한 종목에서만 매도 토글이 나타나며, 한도는 가상 예산이 아니라 이 서비스로 보유한 실제 수량입니다.
- 체결 여부는 자동으로 감시하지 않습니다. 지정가 주문만 사용자가 버튼을 눌렀을 때 KIS에 확인합니다(시장가는 접수 즉시 완료로 취급).
- 회고 화면의 현재가는 KIS 조회에 실패하면 `—`로 표시됩니다.
- Google 계정이 없으면 주문을 실행할 수 없습니다. (조회·회고 열람은 로그인 없이 가능)

## 프로젝트 2와의 관계

이 프로젝트는 프로젝트 2에서 작성한 **KIS 모의투자 텔레그램 AI 에이전트 기획서**를 웹으로 옮긴 것입니다.

**옮기면서 새로 가능해진 것**

1. 근거 히스토리를 한 화면에서 되돌아볼 수 있습니다 (대화에서는 스크롤로 찾을 수 없었습니다)
2. 4턴 대화가 1화면으로 압축되어 대기 상태·만료 관리가 사라졌습니다
3. 당시가와 현재가를 표로 대조할 수 있습니다
4. 링크 하나로 아무나 접속할 수 있습니다
5. **근거를 고르지 않으면 주문 버튼이 눌리지 않습니다** — 대화에서는 답하지 않고 이탈할 수 있었습니다

5번 덕분에 근거 기록률이 측정 지표에서 **구조적 보장**으로 바뀌었고, 그래서 목표를 "근거를 남기는가"에서 **"남긴 근거를 되돌아보고 설명할 수 있는가"**로 올릴 수 있었습니다.
