## 2. KIS Open API

### 사용하는 엔드포인트

| 용도 | 호출 성격 | 장 시간 밖 동작 | 담당 흐름 |
|---|---|---|---|
| 접근토큰 발급 | POST | ✅ | 전부 |
| 계좌 잔고 조회 | GET | ✅ (전일 기준) | 흐름 B |
| 종목 현재가 조회 | GET | ✅ (전일 종가) | 흐름 C, E |
| 국내주식 현금 매수 주문 | POST | ❌ | 흐름 D |

### 🔴 조회는 휴장일에도 동작합니다

**이 사실이 4일 일정을 성립시킵니다.**

```
Day 3(토) · Day 4(일) 은 휴장일입니다.
조회가 휴장일에 동작하지 않으면 이틀 동안 아무 화면도 테스트할 수 없습니다.
```

프로젝트 2에서 확인된 사실이므로 가정이 아니라 사실로 씁니다. 단, **Day 1에 재확인**합니다(환경이 n8n → Vercel로 바뀌었으므로).

### 🔴 Vercel에서의 위험 2가지

| # | 위험 | 확인 시점 | 대응 |
|---:|---|---|---|
| 1 | **고정 IP가 없음.** KIS 앱키에 접근 IP 제한이 걸려 있으면 전면 실패 | Day 1 첫 2h | [[../01_Baseline/02_project_baseline\|기준선]] 6절 대안 시나리오 |
| 2 | **토큰 발급 호출 제한.** 요청마다 발급하면 차단 | Day 1 | `kis_tokens` 캐시 |

### 인증 정보

| 환경변수 | 용도 |
|---|---|
| `KIS_APP_KEY` | 앱키 |
| `KIS_APP_SECRET` | 앱시크릿 |
| `KIS_ACCOUNT_NO` | 계좌번호 (앞 8자리) |
| `KIS_ACCOUNT_PRODUCT_CODE` | 계좌 상품코드 (뒤 2자리) |
| `KIS_BASE_URL` | 모의투자 도메인 |

> 🔴 **전부 `NEXT_PUBLIC_` 없이 등록합니다.** 프로젝트 2에서는 n8n Credential에 있었으므로 이 실수가 불가능했습니다. Next.js에서는 접두사 하나로 앱키가 브라우저에 노출됩니다. **Day 1 배포 전에 이름을 확인합니다.**

### 🔴 Vercel 환경변수 등록이 Day 1 작업입니다

KIS 자격증명은 현재 **n8n Credential 안에만 있습니다.** `.env`에는 Supabase와 Gemini만 있습니다.

```
확인 결과 (.env):
  NEXT_PUBLIC_SUPABASE_URL      ✅
  NEXT_PUBLIC_SUPABASE_ANON_KEY ✅
  GEMINI_API_KEY                ✅
  KIS_*                         ❌ 없음 ← Day 1에 옮겨야 함
```

n8n에서 값을 꺼내 로컬 `.env.local`과 Vercel 환경변수에 각각 등록합니다. **약 0.3h.**

## 3. Gemini API

### 3개 용도

| ID | 용도 | 입력 | 출력 | 담당 |
|---|---|---|---|---|
| AI-1 | 계좌·시세 숫자 해석 | 잔고 또는 시세 JSON | 초보자용 3~4문장 | Must |
| AI-2 | 근거 회고 코멘트 | 근거 목록 전체 | 편중 지적 + 질문 1개 | Must |
| AI-3 | 투자용어 설명 | 용어 1개 | 초보자용 설명 | Should |

### 🔴 프롬프트 공통 금지 규칙

모든 프롬프트에 다음을 명시합니다.

```
- 특정 종목의 매수·매도를 권유하지 마십시오.
- 목표 가격이나 수익률을 예측하지 마십시오.
- 사용자의 판단이 옳거나 틀렸다고 평가하지 마십시오.
- 숫자가 무엇을 의미하는지 설명하는 데까지만 답하십시오.
```

**이유 2가지**

| 이유 | 설명 |
|---|---|
| 법적 | 특정 종목 매수 권유는 유사투자자문 영역에 접근합니다 |
| 목적 | AI 의견을 따라가면 **사용자가 자기 판단을 설명하게 만든다**는 목적과 정반대가 됩니다 |

> [[../05_Scope/02_definition_of_done|완료 기준]]에서 AI 응답 30건에 권유 표현이 0건인지 검사합니다.

### 출력 형식

| 항목 | 결정 |
|---|---|
| 응답 형식 | 일반 텍스트 (JSON 강제하지 않음) |
| 길이 제한 | 프롬프트에서 "4문장 이내" 지시 |
| 스트리밍 | 사용하지 않음 |
| 타임아웃 | 8초 (Vercel 제한 10초보다 이르게) |

> **스트리밍을 쓰지 않는 이유**: 구현 시간이 늘고, 실패 처리가 복잡해집니다. 4문장은 스트리밍 없이도 충분히 빠릅니다. 4일 일정에서 체감 개선을 위한 복잡도는 사치입니다.

## 4. Supabase

| 항목 | 내용 |
|---|---|
| 접속 (브라우저) | `NEXT_PUBLIC_SUPABASE_URL` + `ANON_KEY`, **읽기만** |
| 접속 (서버) | 동일 키. RLS를 우회하지 않음 |
| service role key | 🔴 **사용하지 않습니다** |

### service role key를 쓰지 않는 이유

`kis_tokens`와 `event_logs`는 RLS 정책이 없어 anon key로 접근할 수 없습니다. 이 두 테이블에 서버가 접근해야 하므로 service role key가 필요해 보입니다.

**대신 이 두 테이블만 `security definer` 함수로 접근합니다.**

```sql
create or replace function get_kis_token()
returns table (access_token text, expires_at timestamptz)
language sql security definer
as $$ select access_token, expires_at from kis_tokens where id = 1 $$;
```

service role key가 유출되면 **모든 테이블에 무제한 접근**이 열립니다. 함수로 제한하면 그 함수가 하는 일만 열립니다.

> ⚠️ **이것은 Should 항목입니다.** Day 1에 시간이 부족하면 service role key를 서버 전용 환경변수로 쓰고, Day 4에 함수로 교체합니다. **그 경우 발표에서 한계로 명시합니다.**

## 6. 소스별 실패가 서비스에 미치는 영향

| 소스 실패 | 계좌 화면 | 종목 화면 | 주문 | 회고 화면 |
|---|---|---|---|---|
| KIS 실패 | ❌ 조회 불가 | ❌ 시세 불가 | ❌ | ⚠️ 현재가 대비만 빠짐 |
| Gemini 실패 | ⚠️ 숫자만 표시 | ⚠️ 숫자만 표시 | ✅ **영향 없음** | ⚠️ 목록만 표시 |
| Supabase 실패 | ⚠️ 숫자는 표시 | ❌ 종목 검색 불가 | ❌ | ❌ |

### 🔴 이 표에서 읽어야 할 것

**Gemini가 죽어도 주문과 근거 기록은 동작합니다.** 주문 경로에 AI를 넣지 않은 결과입니다.

**회고 화면은 KIS가 죽어도 대부분 동작합니다.** 저장된 데이터만으로 그려지기 때문입니다. → **발표 시연의 최종 안전판은 회고 화면입니다.**
