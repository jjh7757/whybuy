**세 제약 모두 계획대로 대응했고, 셋 다 프로젝트를 위협하지 않았습니다.** 순서 원칙("불확실한 것을 먼저")이 통했습니다.

### 🔴 정작 터진 것은 이 목록에 없었습니다

**KIS의 앱키당 초당 1건 제한(`EGW00201`)입니다.**

이 목록은 "KIS에 **연결이 되는가**"만 걱정했고 "**얼마나 자주** 부를 수 있는가"는 위험으로 잡지 않았습니다. 기능이 늘수록(인기 종목 목록 → 분봉 차트 → 배당 → 재무 → 주문) 서로 다른 자리에서 따로 터졌고, 그때마다 국소적으로 막다가 결국 **모든 KIS 호출이 거치는 지점에 전역 큐를 두어**(`lib/kis.ts`) 근본 해결했습니다. 부수적으로 `/api/chart`는 분봉을 나눠 받느라 실행 시간이 늘어 `maxDuration = 45`가 필요해졌습니다.

> **교훈**: 외부 API의 위험을 "되는가/안 되는가"로만 잡으면 절반만 본 것입니다. **호출 빈도 제한을 위험 목록에 넣습니다.** 자세한 경위는 [[07_Submit/02_scope_reduction|범위 축소 설명서]] 7절에 있습니다.

> ⚠️ **주문 시연 녹화(마일스톤 6.2)는 이 문서를 갱신하는 시점에 완료 여부를 확인하지 못했습니다.** 실주문 통과(6.1)는 8/6에 끝났지만 녹화는 별도 작업이고, **거래일은 오늘(8/7 15:30)로 끝납니다.** 아직 안 했다면 지금이 마지막 기회입니다 — [[06_WBS/02_milestones|4일 마일스톤]] Day 2.
